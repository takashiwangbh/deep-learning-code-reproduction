# Proximal Policy Optimization（PPO）

## 1. 出处、提出者与意义

John Schulman、Filip Wolski、Prafulla Dhariwal、Alec Radford 和 Oleg Klimov 在 [Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347)（2017）中提出 PPO。与 DQN 估计动作价值后再选动作不同，PPO 直接学习一个“在当前状态下各动作有多可能”的策略，同时学习状态价值。它允许反复利用一批新收集的数据更新参数，又用裁剪目标限制单次策略变化。

本项目针对离散动作，写出策略/价值网络、优势估计和裁剪损失。示例使用随机小批次展示更新式，不包含游戏环境、连续动作分布或论文基准成绩。

## 2. 源码导航与直观解释

[ppo.py](ppo.py) 的 `ActorCritic` 共享前面的特征层，分别输出动作分布与状态价值。先读 `generalized_advantage_estimate`：它从一次交互轨迹的末尾往前计算每一步动作比平均预期“好多少”。再读 `clipped_policy_loss`，看新旧策略概率之比怎样被裁剪。最后看 `ppo_update`：同一批旧策略收集的样本被用于数轮更新，策略损失、价值损失与熵奖励合成总损失。

从仓库根目录运行 `python 'PPO/ppo.py'`。示例中观察值 `[B,4]`，输出离散动作概率与每个状态一个价值；打印的一次损失只用于检查代码可运行。真实训练需加入环境交互、轨迹收集、终止标记，以及按批次更新与评估。

## 3. 数学解释

价值网络给出 `V(sₜ)`。先计算时间差分误差 `δₜ = rₜ + γ(1−doneₜ)V(sₜ₊₁) − V(sₜ)`；再从后往前累积 `Aₜ = δₜ + γλ(1−doneₜ)Aₜ₊₁`。`Aₜ` 称为优势：正数表示这一步比价值网络原先预期好，负数表示更差。`γ` 折扣未来，`λ` 控制用多长的后续信息；终止位置用 `done=1` 切断延续。源码中的 `generalized_advantage_estimate` 逐行对应这两式。

更新策略时，令 `rₜ(θ)=πθ(aₜ|sₜ)/πold(aₜ|sₜ)` 为新旧策略对已执行动作的概率比。PPO 最大化 `min(rₜAₜ, clip(rₜ,1−ε,1+ε)Aₜ)`，代码把它取负号，作为最小化损失。若 `Aₜ>0`，希望提高动作概率，但 `clip` 防止奖励继续推动过大的比值；负优势时也限制反方向的大步变化。价值分支另用均方误差学习 `Aₜ+V(sₜ)` 形成的回报目标。
